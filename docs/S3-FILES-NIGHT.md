# Ночной переезд вложений чата в S3 (Timeweb)

Готовлено 30.09.2026. Выполнять ночью, когда клиенты не пишут, вместе с владельцем.

## Что переезжает и что нет

- **Переезжают вложения переписки** (фото, PDF, документы): `/opt/alphabet-chat-api/private_uploads` → бакет Timeweb `78b153a5-0492-4779-87b0-013279cbfb8f`, папка `chat-v8/files/`. Это единственные файлы чата, которые растут каждый день.
- **Тексты сообщений остаются в базе**: занимают мало, по ним нужен поиск.
- **Аватары операторов и виджета остаются на диске**: их отдаёт nginx напрямую (`/uploads/`, `/widget-uploads/`), файлов несколько штук.

## Как работает после переезда

- Ссылки для клиентов и операторов прежние (`/api/chat-v8/files/<id>?cap=…`, живут 10 минут). Сервер берёт файл из S3 и отдаёт — правок в приложении, виджете, nginx и CSP не нужно.
- Нет файла в S3 — сервер ищет его на диске (переходный период).
- S3 не ответил при загрузке — файл сохраняется на диск, отправка не срывается; в журнале строка `[files] S3 недоступен`. Скрипт переноса подберёт такие файлы.
- Откат на диск: файлы, уже лежащие только в S3, продолжают открываться.
- Настройки: `CHAT_FILE_STORE` (`local`/`s3`) и `CHAT_S3_*` в `/opt/alphabet-chat-api/.env.chat-v8` (права 600). Регион `ru-1`, адрес `https://s3.twcstorage.ru` — по документации Timeweb.

## Порядок

1. **Выложить beta.7** (сервер и виджет) обычным порядком: `scripts/prepare-release.ps1` → план `scripts/deploy-server-v8.ps1` → применить с суммами из плана. Код S3 приезжает выключенным: без `CHAT_FILE_STORE=s3` файлы по-прежнему на диске.
2. **Ключи** — вводит владелец: в PowerShell из папки проекта `.\scripts\set-chat-s3.ps1`, затем Access Key и Secret Access Key из панели Timeweb (бакет → «Подключение»). Ввод скрытый, ключи уходят на сервер через SSH и не попадают ни в чат, ни в файлы проекта.
3. **Проверка доступа** (скрипт запускается из каталога текущего выпуска; одинарные кавычки — чтобы PowerShell не трогал `$( )`):
   `ssh root@5.129.241.152 'cd "$(systemctl show -p WorkingDirectory --value alphabet-chat-api)" && node scripts/files-to-s3.mjs --check'`
   Ждём `"ok":true`. Ошибка `AuthorizationHeaderMalformed` или `SignatureDoesNotMatch` — проверить регион и ключи; ошибка адреса бакета — попробовать `CHAT_S3_PATH_STYLE=true`.
4. **План и перенос**: тот же каталог, `node scripts/files-to-s3.mjs` (план) → `node scripts/files-to-s3.mjs --apply`. Ждём `"problems":[]` и `copied` = `to_copy`.
5. **Включить S3**: `.\scripts\set-chat-s3.ps1 -Set s3`, затем `ssh root@5.129.241.152 "systemctl restart alphabet-chat-api"` — перезапуск пара секунд, чат переподключится сам.
6. **Проверить**: открыть в приложении старое вложение; отправить новое фото из приложения и из виджета; `files-to-s3.mjs` (план) показывает `to_copy: 0`; в `journalctl -u alphabet-chat-api --since "-10 min"` нет `[files] S3`.
7. **Через неделю** без жалоб: `node scripts/files-to-s3.mjs --prune-local` — удаляет с диска только файлы, которые лежат в S3 того же размера.

**Откат:** `.\scripts\set-chat-s3.ps1 -Set local` и перезапуск сервиса. Файлы на диске не трогаются до шага 7.

## Место на сервере — важнее переезда чата

30.09 диск сервера заполнен на **96%** (92 из 96 ГБ, свободно 4,8 ГБ). Файлы чата занимают ~8 МБ — дело не в них. По списку каталогов место держат старые копии и архивы в `/opt` (`_backup_alphabet_app_*`, `alphabet_app_backups`, `backups`, `backups_prod`, `old_backups`, `prod_backup_*.tar.gz`, `supabase`, `alphabet_v*`) и в `/var/www` (`medya-site-backups`, `medya-site-releases`).

Ночью: замерить размеры (`du` на медленном диске — только ночью), вместе с владельцем решить, что из архивов переложить в тот же бакет S3 (отдельная папка, например `server-backups/`) со сверкой размеров, и только после этого удалять с сервера. Ничего не удалять без решения владельца: это данные Alphabet и сайтов.
