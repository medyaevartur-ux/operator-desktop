# Трек B — Дизайн-система Material Design 3 (фундамент полного редизайна)

Дата: 2026-06-07
Статус: на утверждение

## Главная идея (и как «с нуля» не ломает поведение)

Делаем **полностью новый визуал с нуля на MD3**, но **не переписываем логику** — она и есть «лучшее и рабочее со старого». Приложение уже грамотно разделено:
- **Логика/данные** (сохраняем 1:1): zustand-сторы (`inbox/auth/visitors/notification/theme/templates/drafts`), API-слой, хуки (`use-inbox`, `use-inbox-realtime`, `use-visitors-realtime`, `use-sla`, `use-typing`, `use-hotkeys`), socket.io, поведения 1–4.
- **Презентация** (переписываем с нуля на MD3): токены, библиотека компонентов, экраны.

То есть «ПОЛНОСТЬЮ новый дизайн» = новый дизайн-слой поверх проверенной логики. Так мы получаем идеальный новый вид **и** гарантируем, что всё работает ровно как настроено (поведения сверяем после каждого экрана).

Платформа: React 19 + Vite + Tauri (web). Официальной React-библиотеки MD3 нет; `@material/web` в maintenance и неудобен в React. Поэтому MD3 реализуем **нативно**: CSS-токены `--md-sys-*` + собственные React-компоненты, управляемые токенами (state layers, ripple, a11y). Это даёт полный контроль и «expressive» без ограничений Material Web.

## Что входит в Трек B (фундамент + флагман)

1. **Токены** `src/styles/md3/` (CSS custom properties):
   - Цвет: полные `--md-sys-color-*` для **светлой и тёмной** схем, сгенерированные из seed-цвета бренда через `@material/material-color-utilities` (тональные палитры, правильные пары `on-*`). 3 уровня контраста — опционально позже.
   - Типографика: type scale (Display/Headline/Title/Body/Label, + emphasized). Шрифт: Roboto Flex (вариативный) как MD3-дефолт, кириллица поддержана.
   - Форма (`--md-sys-shape-corner-*`), elevation (тональная, не тени), motion (cubic-bezier + длительности), spacing 8dp.
2. **ThemeProvider** `src/theme/`: режим light/dark/system + seed → схема; персист (расширяем `theme.store`). Мгновенное переключение.
3. **Иконки**: Material Symbols Rounded (вариативный шрифт) + компонент `<Icon>`. Миграция с lucide постепенная (lucide остаётся рабочим до полной замены — без «дыр»).
4. **Библиотека MD3** `src/components/md3/`: Button (filled/tonal/outlined/text/elevated + icon, размеры), TextField (outlined/filled), Card (filled/outlined/elevated), Chip (assist/filter/input/suggestion), Switch, Checkbox, Radio, Menu, Dialog, Snackbar (мост к текущему Toast), Tooltip, Tabs (primary/secondary), NavigationRail, TopAppBar (small/medium/large), List/ListItem, Badge, Progress (linear/circular), Avatar, Divider, SegmentedButton, FAB/Extended FAB, Search. Все — токен-driven, с состояниями (hover/focus/pressed/disabled), ripple и доступностью (роли, фокус, 48dp таргеты, контраст 4.5:1).
5. **Адаптивный App Shell на MD3**: NavigationRail (≥ medium) ↔ Navigation Bar снизу (compact), MD3 TopAppBar. Переносим `app-shell` + `inbox-rail` + `top-bar`.
6. **Флагманский экран — «Чаты» (inbox)** целиком на MD3 как эталон и образец для остальных: sidebar диалогов (List/ListItem + presence), лента (бабблы, группировка, реакции, reply, картинки/лайтбокс), composer (TextField + chips шаблонов + вложения), панель деталей (Cards). Вся логика — из существующих хуков/сторов.

## Декомпозиция дальше (Трек C — отдельными циклами, экран за экраном)
Очередь · Посетители (+ presence/путь — стык с Треком D) · Шаблоны · Операторы · Настройки · Конфигуратор виджета · Логи · мобильные shell/list/view · командная палитра 2.0. Каждый экран мигрирует на готовую библиотеку MD3, с проверкой поведения.

## Дефолты, которые выбираю (делегировано — «доверяю тебе»), их легко сменить
- **Seed/вайб (выбран пользователем): «Глубокий индиго»** — строгий сине-фиолетовый «night»-вайб, фокусный для рабочего инструмента. Seed ≈ `#4F5BD5` (индиго), вторичный — приглушённый сине-серый, третичный — мягкий фиолет-акцент. Seed — один токен; сменить = одна строка.
- **Темы:** светлая + тёмная, по умолчанию системная.
- **Иконки:** Material Symbols Rounded.
- **Плотность:** комфортная для рабочего инструмента (компактнее, чем дефолт MD3, но в пределах 8dp-сетки).

## Жёсткие инварианты (сверяем после каждого экрана)
Поведения 1–4 (трей, маршрутизация по онлайну, разделение диалогов, presence); composer (реакции/reply/файлы/typing/черновики); claim-on-open/передача/фильтры/поиск; шаблоны; посетители; конфигуратор виджета; realtime-события; апдейтер/выпуск (Трек A). Виджет на сайте, ВК-бот, widget-бот — вне приложения, не трогаем.

## Проверка готовности Трека B
- `npm run build` (tsc+vite) зелёный; приложение запускается.
- Светлая/тёмная темы, переключение, персист.
- Экран «Чаты» визуально новый (MD3) и функционально идентичен старому: все действия работают (отправка, реакции, reply, вложения, claim, передача, фильтры, поиск, presence).
- Поведения 1–4 не регрессировали.
- MD3-самоаудит флагмана ≥ 8/10 по ключевым категориям (цвет/типографика/форма/компоненты/доступность).

## Риски и как держим качество
- Поверхность огромная → строго инкрементально: сначала библиотека + шелл + 1 экран; старые компоненты живут, пока не заменены (никаких «полусломанных» состояний).
- Каждый экран = отдельный коммит + проверка поведения перед переходом к следующему.
- Сборка через апдейтер 5.1.7+ доставит редизайн автоматически (Трек A это уже чинит).
