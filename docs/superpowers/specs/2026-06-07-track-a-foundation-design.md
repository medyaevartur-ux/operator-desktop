# Трек A — Фундамент и гигиена (operator-desktop / chat-api)

Дата: 2026-06-07
Статус: дизайн утверждён («решай сам» = делегирование)

## Контекст

Большой запрос пользователя — «построить полноценное Jivo с нуля» (Material Design-редизайн,
интеллект по посетителям, полнота функций). Это декомпозировано на треки A–E; каждый проходит
свой цикл дизайн → план → реализация → деплой.

**Трек A** — обязательный фундамент: без рабочего канала доставки обновлений ни один
последующий «с нуля»-релиз не доедет до оператора. Поэтому он первый.

## Диагноз «плашка обновить не прилетает» (выполнен)

Канал доставки исправен на всех уровнях:
- nginx активного `zhivaya-skazka.ru` проксирует `/api/updater/` → `127.0.0.1:3010`.
- Endpoint `/api/updater/check`: `current_version=5.1.4` → `200` + манифест 5.1.5; `=5.1.5` → `204`.
- Клиент `src/components/updater.tsx`: `check()` → тост «Обновить» → `downloadAndInstall` → `relaunch`;
  проверка через 5с после старта и каждые 30 мин.

**Корневая причина:** опубликована 5.1.5, оператор запущен на 5.1.5 → «обновлений нет».
Правки 5.1.6 (re-join, авто-away, звук нового чата) закоммичены не были и не собирались —
новее ничего нет, плашке неоткуда взяться. Поломки нет; 5.1.6 просто не довезли.

**Скрытые риски (закрыть, чтобы не повторялось):**
1. Сравнение версий в `updater.ts` — строковое `===`, не семвер. Сегодня безвредно (Tauri
   сверяет семвер на клиенте), но хрупко.
2. Ошибки `check()` уходят только в `console.error` — молчаливый сбой при будущем рассогласовании
   ключа подписи ↔ pubkey. Оператор не увидит ничего.

## Объём трека A (3 блока)

### 1. Апдейтер: надёжность + довезти 5.1.6
- `chat-api/src/routes/updater.ts`: семвер-сравнение (предлагать только если манифест строго
  новее `current_version`), лёгкая валидация формы манифеста; сохранить `204` когда нет апдейта.
- `updater.tsx`: видимое (ненавязчивое) состояние ошибки проверки + ручная кнопка «Проверить
  обновления» в настройках. Молчаливые сбои становятся заметными.
- Release-скрипт одной командой: бамп версии (package.json + tauri.conf.json) → `tauri build` →
  копирование `.zip`+`.sig` в releases/ → обновление `latest.json` на сервере → авто-проверка
  endpoint. Убивает класс ошибок «забыл обновить latest.json».
- Проверка соответствия pubkey ↔ ключа подписи на этапе деплоя (локальный `check()` до публикации).

### 2. Аудит безопасности + закрытие дыр (chat-api)
- Эндпоинты без auth: `PATCH /api/operators/:id/online` (сейчас без авторизации) — закрыть/ограничить.
  Пройти все роуты на пропущенные auth/проверки владения ресурсом.
- `/api/widget/*` (без auth by design): rate-limit, проверка «посетитель пишет только в свою
  сессию», лимиты на размер ввода.
- JWT: срок жизни, сила секрета, отсутствие утечки токена в логи; CORS; утечки в текстах ошибок.
- Результат: отчёт findings с severity; фикс High/Critical в этом же треке. Low/Medium — бэклог.

### 3. Гигиена + выпуск 5.1.6
- `.env.production` уже снят с трекинга, `.gitignore` дополнен `.env.*`. В истории утёк только
  публичный URL API (не секрет) → переписывание истории не требуется; зафиксировать в отчёте.
- Закоммитить готовый 5.1.6 → собрать → выкатить release-скриптом → проверить, что клиент 5.1.5
  реально получает плашку 5.1.6.
- Проверить старый пункт «664 рестарта» chat-api (pm2/systemd), если актуально.

## Не ломать (инварианты)
- ВК-бот (Python `alphabet_v3`) и widget-бот (Node `alphabet-chat-api/services/widget-bot`) — не трогаем.
- Виджет на сайте (`/var/www/widget/`) — не трогаем в этом треке.
- Поведения 1–4 (трей, маршрутизация по онлайну, разделение диалогов, presence) — не регрессировать.

## Критерии готовности (verification)
1. Клиент на 5.1.5 после старта получает плашку «Обновление v5.1.6», ставит её и перезапускается.
2. Endpoint: семвер-сравнение проверено (старее → манифест; равно/новее → 204).
3. Findings High/Critical закрыты и перепроверены; отчёт в репозитории.
4. Регрессий нет: чат, виджет, ВК-бот, widget-бот, операторские поведения 1–4 работают.
