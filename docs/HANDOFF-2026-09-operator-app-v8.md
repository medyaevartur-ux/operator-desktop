## 3. Что уже есть и работает

**Приложение**: экраны очереди/чатов, посетителей (+ статистика, карта пути),
операторов, шаблонов, настроек и конструктора виджета (Monaco, live-превью
через `?raw`-импорт `widget.js`), логов. Стейт — zustand (`src/store/*`), своё
навигационное состояние вместо роутера (`app-router.tsx` +
`navigation.store.ts`), API — тонкая обёртка `src/lib/api.ts`, реалтайм —
`src/lib/socket.ts` + `src/features/inbox/use-inbox-realtime.ts`.

**Уведомления сейчас**:
- Windows:
  - звук синтезируется Web Audio (`notification.store.ts`, `SYNTH_SOUNDS`), есть DND и повтор каждые 18 с;
  - системный тост через `@tauri-apps/plugin-notification`, клик открывает чат;
  - трей: иконка перерисовывается с красной точкой (`src-tauri/src/tray_icon.rs`), в заголовке окна `(N)`;
  - есть «сворачивать в трей».
- Android: FCM. Токен кладёт Kotlin в `window.__FCM_TOKEN`, JS отправляет на `POST /api/push/register`. Тап по пушу вызывает `window.__openSessionFromPush(sessionId)`. Сервер шлёт через `src/services/push.ts`: всем операторам сессии или всем активным, мёртвые токены удаляет. Канал уведомлений `chat_messages`.

**Виджет**:
- Shadow DOM, REST + socket.io на `/ws`, лёгкий сокет висит ещё до открытия чата: пинг и приглашения;
- бот-сценарии, файлы, UTM, рейтинг, проактивные триггеры, офлайн-форма, часы работы, домены;
- мобильный режим bottom-sheet.

**Выпуск (Windows)**:
- `scripts/release.ps1`: бампит версию, собирает, кладёт `.nsis.zip`, `.sig` и `latest.json` в `releases/` и **печатает** команды `scp` на `/var/www/updates/operator-desktop/`;
- апдейтер ходит на `https://zhivaya-skazka.ru/api/updater/check`;
- на сервере сейчас лежит 7.1.0.

## 4. Жёсткие правила (нарушение = авария)

1. **Сайт магазина не трогать**: репозиторий `D:\Projects\zhivaya-skazka`,
   pm2-процесс `zhivaya-skazka`, `/var/www/zhivaya-skazka`. Никаких
   `pm2 restart all`, `killall node`, перезагрузок сервера.
2. **Порядок выкладки виджета и сервера**: сначала `widget.min.js` в
   `/var/www/widget/`, потом сервер. Эндпоинты `/api/widget/sessions/*` требуют
   заголовок `X-Visitor-Id` (добавляется централизованно в `api()` виджета;
   на сервере `assertOwner()`/`checkSessionOwner()`); старый закэшированный
   виджет живёт до часа. Заголовок из `api()` не убирать.
3. **Перед любой правкой кода на сервере** — сначала завести git (см. фазу 0);
   до этого — бэкап файла рядом. Сейчас в `src/` россыпь `*.bak-*` и каталогов
   `_bak-*` — это единственная история.
4. **`npm run tauri build` на этой машине зависает** после NSIS-бандлинга: ждать
   появления `src-tauri/target/release/bundle/nsis/Zhivaya-Skazka-Operator_<ver>_x64-setup.nsis.zip`,
   убить процессы tauri/cargo и подписать вручную:
   `npx tauri signer sign -f src-tauri/keys/update.key -p "" <zip>`.
5. `release.ps1` **не бампит `src-tauri/Cargo.toml`** — править руками (или
   починить скрипт).
6. CSP в `tauri.conf.json` включён, но в собранном приложении не проверялся —
   каждый релиз: Monaco, превью виджета, шрифты, аватары, сокет. Аварийный
   откат — `"csp": null`.
7. Секреты не печатать в чат/логи; из `.env` показывать только имена.
8. Никаких поисков по всему диску (`find /`, `grep -r` по дереву с
   `node_modules`) — зависают часами.

## 6. План работ на 2026 (версия 8)

Порядок фаз важен: без фазы 0 всё остальное нельзя безопасно выкатывать.
Каждая фаза закрывается проверяемыми критериями.

### Фаза 0 — фундамент (1–2 недели)
- Завести приватный репозиторий сервера (`alphabet-chat-api`): снять код с
  прода как есть, вычистить `.bak`, первый коммит = прод. Выкладка — скриптом
  (`git pull` → `npm ci` → `systemctl restart`) с сохранением предыдущего SHA
  для отката.
- Снять схему БД `pg_dump --schema-only` в репо; ввести миграции
  (node-pg-migrate или аналог) с baseline = текущая схема.
- ESLint + Prettier + Vitest в приложении и на сервере; первые тесты на
  критичное: авторизация, владение сессией (`X-Visitor-Id`), выдача пушей.
- GitHub Actions: типы, линт, тесты на PR; сборка Windows-установщика на
  `windows-latest` с подписью апдейтера из секрета репозитория (заодно
  обходит зависание локальной сборки); сборка Android AAB/APK.
- `release.ps1`/CI бампит все три версии (package.json, tauri.conf.json,
  Cargo.toml), ставит git-тег.
- Сбор ошибок: self-hosted GlitchTip/Sentry для приложения и сервера.

**Готово, когда**: сервер разворачивается из git одной командой и
откатывается; PR со сломанным типом не проходит CI; установщик и APK
собираются в CI.

### Фаза 1 — безопасность и сессии
- Сокет: токен в `auth` при подключении, проверка на сервере, комнаты по
  правам оператора (D4).
- Короткий access-токен (15–60 мин) + refresh-токен с отзывом; хранение в
  защищённом хранилище ОС (`tauri-plugin-stronghold` или keyring на
  Windows/Android Keystore) вместо `localStorage` (D3). Оператор по-прежнему не
  разлогинивается без явного выхода — refresh делает это прозрачно.
- CORS по белому списку для панели, отдельно открытый для виджета (D5);
  rate-limit на логин, загрузку, бот-события; закрыть F1–F7 (D6).

**Готово, когда**: без токена сокет не получает ни одного события; украденный
refresh отзывается из админки; аудит 07.06 — все пункты «закрыто» с тестом.

### Фаза 2 — уведомления «всегда и везде» (главная)
Сначала сервер, потом клиенты.

**Сервер — единый слой доставки**
- Таблица устройств вместо `push_tokens`: `operator_id, platform (windows|android|web), provider (fcm|rustore|webpush|socket), token, app_version, last_seen_at`.
- Сервис `notify(event)`:
  - кому доставлять (назначенный оператор → все онлайн → все);
  - провайдеры параллельно;
  - дедупликация по `event_id`, повторы с backoff, журнал доставки;
  - удаление мёртвых токенов.
- Серверные настройки оператора: какие события, DND-расписание, звук.
- **Эскалация**: чат без ответа N минут — повторный пуш и всем операторам.
- API непрочитанного для догонялки после сна или офлайна.
- **Россия**: FCM доставляется с перебоями — добавить **RuStore Push** вторым каналом на Android (SDK + серверный REST). Решение по Huawei — у заказчика.

**Windows**
- `tauri-plugin-single-instance` (второй запуск фокусирует окно), `tauri-plugin-autostart` (галочка «запускать с Windows», по умолчанию вкл), приложение живёт в трее.
- Нативные тосты WinRT с действиями «Ответить» (текст прямо в тосте), «Открыть», «Прочитано»: рецепт в `docs/notifications.md`, crate `windows`. У приложения должен быть зарегистрированный AppUserModelID, иначе тосты не группируются и теряют действия.
- Наложение счётчика на иконку в панели задач (`ITaskbarList3::SetOverlayIcon`) и цифра на иконке трея.
- Надёжность сокета:
  - переподключение после сна и смены сети (события питания и сети ОС);
  - heartbeat;
  - догрузка пропущенного через API непрочитанного;
  - в заголовке и трее видно «нет связи».
- Звук: выбор из набора (подключить или удалить мёртвые mp3), громкость, тест звука в настройках.

**Android**
- Высокоприоритетные data-сообщения. Уведомление строит само приложение: канал на тип события, группировка по чату, стиль переписки (`MessagingStyle`), действие «Ответить» (`RemoteInput` → REST с токеном), «Прочитано», тап открывает чат.
- Android 13+: запрос `POST_NOTIFICATIONS`; экран «уведомления приходят с задержкой?» с переходом к отключению оптимизации батареи.
- Обновление токена (`onNewToken`) и повторная регистрация при входе.
- Не дублировать уведомление, когда открыт этот же чат.

**Готово, когда** пройдена матрица ручных тестов, всё в журнале доставки:

| Состояние приложения | Windows | Android |
|---|---|---|
| открыто на этом чате | без тоста, звук по настройке | без пуша |
| открыто, другой чат | тост + звук + счётчик | уведомление в шторке |
| свёрнуто / в трее | тост + звук + счётчик | уведомление |
| закрыто | автозапуск с Windows; если выгружено — догонялка при старте | пуш FCM/RuStore |
| сон ПК / экран заблокирован | после пробуждения пропущенные приходят за 10 с | Doze: пуш высокого приоритета |
| нет сети → сеть появилась | переподключение и догонялка | догонялка при открытии |

Плюс «Ответить» из уведомления доходит посетителю на обеих платформах.

### Фаза 5 — мобильная веб-версия панели (для удобства)
- Тот же React-билд как PWA на отдельном поддомене (например `operator.zhivaya-skazka.ru`, отдельный server-блок nginx, **не на путях сайта**).
- `manifest.json`, иконки, установка на главный экран. Существующий `public/sw.js` расширить до Web Push (VAPID) — это же даёт уведомления на iPhone (iOS 16.4+ для установленного PWA) без отдельного iOS-приложения.

**Готово, когда**: панель открывается с телефона, ставится на главный экран, получает Web Push.

### Фаза 6 — паритет с Jivo (бэклог, по приоритету заказчика)
Сверить с `docs/superpowers/specs/2026-06-07-feature-inventory.md` и довести:
- передача чата другому оператору с комментарием;
- внутренние заметки;
- быстрые ответы с переменными;
- предпросмотр набора посетителя (уже есть `typing_content`);
- карточка посетителя: страницы, UTM, прошлые диалоги, контакты;
- поиск по истории;
- статусы оператора с авто-«отошёл»;
- лимит одновременных чатов и распределение очереди;
- офлайн-сообщения на почту или в Telegram;
- статистика: время ответа, пропущенные, оценки;
- несколько сайтов и виджетов на одном аккаунте;
- каналы Telegram/VK в общий инбокс (в коде есть следы VK-бота — `vk_bot_attachments`).

### Фаза 7 — выпуск и сопровождение

- Раздел в панели «Скачать приложение»: Windows и Android по постоянным ссылкам.
